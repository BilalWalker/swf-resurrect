# Requirements Document

## Introduction

The Pipeline and the Verify_Stage are proven on two samples, `clickgoto` and `tweendemo`. Both contain only solid-fill rectangles and both score 100 percent Overall_Match. That proves the plumbing, not breadth. This spec proves SWF Resurrect on richer content and uses the Verify_Stage to find and fix what breaks.

The spec has two parts. The requirements below are the contract. Appendix A holds the discovery evidence gathered before the requirements were written: the approved samples, what FFDec exports for each feature, what Pixi 8.22 draws, a gap table of what the Pipeline does today, the licence findings and a review log. Every claim in the appendix was checked by running a command or reading the named source; claims that were not checked say so.

Decisions already taken by the user and recorded here:

- Eight SWFs are approved as Breadth_Samples (Requirement 3.1, Appendix A.2). Seven are committed. `avm2/static_text` is not committed: its embedded font outlines have no established licence, so it is fetched on demand into `.work/samples/` by a script, checked against a SHA-256, and measured when present (Requirements 3 and 20). The `clipDepth` smoke file is not one of the eight.
- Package-qualified classes are supported end to end before any sample is admitted: a SymbolClass name `pkg.Cls` resolves to `scripts/pkg/Cls.as`, Emit writes `src/pkg/Cls.ts`, and the registry key stays the dotted name (Requirement 18). No Trace_Score floor of 0 is accepted as a stand-in for this work.
- `DisplayObject.stage` is added now, together with package support, as a minimal Stage_Object that is the parent of the root, and not as an alias of the root clip (Requirement 19).
- Every admitted sample whose Overall_Match is below 100 gets its differing regions attributed to a cause, each cause fixed or recorded as a Known_Visual_Limit (Requirement 21).
- Static text and bitmap fills are built, not cut (Requirements 9 and 10). Anything that is still not drawn is a Named_Limit under the generic rule of Requirement 2.
- Colour offsets are evaluated with the Pixi `ColorMatrixFilter` and built only if the render is an Exact_Render: zero differing pixels against the FFDec Reference_Frame under the unchanged Verify_Tolerance (Requirement 13).
- `TextField` stays out of this spec; it gets its own spec next. Dynamic text stays a Named_Limit (Requirement 11).
- The user approved the Shape_JSON_Path (render path (b)) as the way a shape reaches the screen. The design still records the measured values of all three Render_Paths (Requirement 7).
- Licence texts live in one place, `samples/LICENSES/`, and every PROVENANCE.md (including those of `clickgoto` and `tweendemo`) points to the text that applies. This is its own task and its own commit (Requirement 3).
- The Replay reads both `num_frames` and `num_ticks` as Ruffle's test runner does (Requirement 14, Appendix A.8) and replays `MouseDown`, `MouseMove` and `MouseUp` as separate pointer events in Ruffle's observed order (Requirement 14, Appendix A.9). Both are Approved_Measurement_Changes, as is the empty-input Replay below, under one condition: `clickgoto` stays at Trace_Score 100 with an unchanged tick count (Requirement 1.7).
- A Reference_Trace with no `input.json` is replayed with empty input for the tick count in `test.toml`; this is the third Approved_Measurement_Change, under the same condition (Requirement 14.23, Requirement 1.7). If neither `num_frames` nor `num_ticks` exists and there is no input, the implementer stops and asks.
- A Replay that throws keeps the lines captured before the failure, compares them as usual and records the failure by name in `problems`; it is not `not-compared` (Requirement 14.22).
- Inside a class body, a bare identifier resolves to an own instance member, an own static member, an inherited static member of a translated superclass, an inherited instance member of a translated superclass or an inherited member of a Shim class, in the explicit order of Requirement 22.1 (the nearest class of the `extends` chain wins), using a member table generated from the Shim's own declarations (Requirement 22). This supersedes any narrow rule for bare `stage`, `mouseX` and `mouseY`. It is part of the package work and comes before any sample is admitted.
- A class that cannot load never costs the visual score: a class whose source is missing, whose emitted file does not parse or whose import does not resolve (and every class that extends or imports such a class) is left out of the registry with a diagnostic, and its symbol falls back to the plain base class (Requirement 23). A class with only type errors stays registered and is reported as loose with its diagnostics, because Vite does not type-check, the visual score uses Timeline_Only_Mode, and a runtime throw is captured by the Replay (Requirement 14.22). `slider_component` keeps an Overall_Match of at least 99.93.
- A sample whose Reference_Trace is empty gets no Trace_Score and no Trace_Score floor: the Verify_Stage reports its behaviour as not-compared with the reason `empty-reference-trace` and never reports 100 for it (Requirement 14.24). This changes how behaviour is reported, not how a score is computed, and raises no score (Requirement 1.11).
- No commit leaves a feature drawn wrongly with only a `console.warn`: the Shape_Function emits a Named_Limit for every gradient and bitmap fill from the task that introduces it (Requirement 2.8).
- The task plan has exactly four checkpoints (Requirement 16). The decision checkpoints are gone: every finding F11 to F18 is decided (Appendix A.6, A.7).
- Each approved SWF is checked for embedded fonts at admission; a font whose licence cannot be established stops the admission (Requirement 3, Appendix A.10).
- The design runs the checks that the discovery left unrun (Requirement 17, Appendix A.7).

The headline findings (details in Appendix A):

- Five of the fifteen candidate SWFs that were run through `npm run pipeline -- ... --verify` stop at Unpack, because the Pipeline requires `symbolClass/symbols.csv` and FFDec writes none when a SWF has no SymbolClass tag.
- Five more stop in Convert with `Unknown symbol N`, because text and button definitions are recorded as unsupported without a character id, so the placement is not dropped.
- A class named `Main` makes Emit write `src/Main.ts` next to the boot file `src/main.ts`. On a case-insensitive file system TypeScript reports error 1261 and every frame ends as `render-failed`.
- Pixi 8.22 `Graphics.svg()` silently draws gradients wrongly (it ignores `gradientTransform`) and draws nothing for bitmap pattern fills. Both give a plausible-looking but wrong frame with only a console warning.
- Masks are dropped and the masked content is drawn unmasked. This is already listed as an unsupported `mask` entry, so it is a named limit, but it costs 16 points of Overall_Match on the `clipDepth` smoke file.
- The Replay reports every `MouseMove` entry as `unsupported-input` and ends the Input_Group at that entry, which shifts the tick of every later entry; three approved samples (`3_joystick`, `slider_component`, `click_block`) contain `MouseMove` entries. Press, drag and release are replayed only as a position-paired click.
- `parseNumFrames` reads only `num_frames`, but three approved samples set `num_ticks` instead; for `3_joystick` the fallback (the Input_Group count) is 19 where Ruffle's `test.toml` says 21.
- Of the eight approved SWFs, six embed no font at all, `click_block` holds a font reference with zero glyphs, and `static_text` embeds 17 glyphs of "Times New Roman" under a Monotype copyright (Appendix A.10). The licence of that font is not established, so `static_text` is fetched on demand and not committed.
- The Pipeline handles class names only as flat file stems. `src/convert/readUnpacked.ts` reads `scripts/<className>.as`; `src/translate/translateStage.ts` lists `.as` files recursively but keys each class by `basename(p, '.as')` and throws `DuplicateClassError` when two packages hold the same simple name; `src/translate/planTranslate.ts` keys `ScriptSource.className` and `siblingClasses` by that stem; `createImportLines` in `src/translate/rewrite.ts` writes `import { X } from './X'` and `import ... from '../shim'`; `planEmitDetailed` in `src/emit/planEmit.ts` writes `src/${name}.ts` and `buildClassesTs` writes `import { N } from './N'`. A SymbolClass name with a package (for example `test_fla.MainTimeline`: FFDec 26.4.0 exports `scripts/test_fla/MainTimeline.as` for `click_block`, checked while updating this spec; the source `code/Interactivity3.as` of `3_joystick` declares `package code`, and the exact SymbolClass string was not read) therefore does not resolve (Requirement 18).

Facts checked in the repository when this spec was written:

- `package.json` already holds `playwright` 1.65.0, `pngjs` 7.0.0 and `pixi.js` 8.22.0 as exact versions. No new dependency is expected.
- `src/verify/core/limits.ts` builds `knownVisualLimits` from three sources: non-zero colour offsets (`colour-offset`), skewed matrices (`skewed-matrix`) and unsupported entries of kind `text`, `button`, `filter`, `mask`, `video` and `morph-shape` (`unsupported-feature`).
- `test/e2e/overallMatch.e2e.test.ts` holds the Overall_Match floor constants `OVERALL_MATCH_FLOOR_CLICKGOTO` and `OVERALL_MATCH_FLOOR_TWEENDEMO`, both 100. `test/unit/clickgotoReplay.test.ts` holds `TRACE_SCORE_FLOOR = 100`. `tweendemo` has no `reference/` directory, so its behaviour is `not-compared`.
- `src/convert/convertModel.ts` drops placements of characters whose kind is `text`, `sound`, `button` or `video` only when the observation carries a character id. `src/convert/ffdecXml.ts` records `unsupportedKinds` observations without reading any id attribute.
- `template/runtime/pixi/pixiBackend.ts` loads each shape with `new Graphics().svg(flattenSvgWrapper(svgText))` and applies colour transforms with `tint` and alpha only.
- `src/verify/core/replayPlan.ts` (`planReplay`, `PlannedClick`, `PlanProblem`) classifies Reference_Input entries and accepts only `Wait`, `MouseDown` and `MouseUp`; it pairs a `MouseUp` with a pending `MouseDown` only when both have the same position, and ends the Input_Group at a `Wait` or at any unsupported entry. `src/verify/edge/replayRunner.ts` applies each planned click after the tick's update with `player.dispatchClick(x, y)`.
- `template/runtime/player.ts` (lines 165 to 173) implements `dispatchClick`: it hit-tests the stage point with `hitTest(buildHitView(this.root), x, y)`, dispatches one bubbling `MouseEvent.CLICK` at the hit object, and calls `syncAll()`. The Player has no other pointer entry point. `template/src/main.ts` (lines 66 to 71) calls `player.dispatchClick(x, y)` from a canvas `pointerdown` listener.
- The Shim (`template/shim/events.ts`, lines 34 and 35) has `MouseEvent.CLICK` only; `Event` marks `click` as bubbling (line 24). A search of `template/shim/*.ts` found no `startDrag`, `stopDrag`, `mouseX`, `mouseY`, `MOUSE_DOWN`, `MOUSE_UP` or `MOUSE_MOVE`.
- `samples/clickgoto/reference/test.toml` holds `num_frames = 32`. `samples/clickgoto/reference/input.json` holds 20 `Wait` and 10 `MouseDown`/`MouseUp` entries (five clicks, each press and release at the same position in two consecutive Input_Groups), which gives 21 Input_Groups. The Replay therefore runs 32 ticks for `clickgoto` today (`tickCount = numFrames ?? groupCount`). `test/unit/clickgotoReplay.test.ts` calls `parseNumFrames(toml)` and `planReplay`.
- `template/shim/ADDED_APIS.md` lists every Shim addition with the fixture line that needs it.
- `.kiro/steering/git-workflow.md` requires commits on the current `wip/` branch, one per top-level task, with `npm run typecheck` and `npm test -- --run` passing, and a stop at every task named "Checkpoint".

## Glossary

- **Pipeline**: The command-line tool (`npm run pipeline`) that runs Unpack, Convert, Translate and Emit, and Verify_Stage with `--verify`.
- **Repository**: The SWF Resurrect git repository.
- **Verify_Stage**: The Pipeline stage of the verify spec that writes the Fidelity_Report and the Fidelity_HTML.
- **Fidelity_Report**: The file `fidelity-report.json` with `visual.overallMatch`, `visual.knownVisualLimits`, the behaviour result and the Trace_Score.
- **Reference_Frame**: A PNG that FFDec exports for one frame number of the original SWF, as defined by the verify spec. It is the acceptance measure for every visual requirement of this spec.
- **Rendered_Frame**: The PNG of the Emitted_Project for one frame number, as defined by the verify spec.
- **Frame_Sample**: The ordered list of frame numbers that the Verify_Stage compares for one SWF, as defined by the verify spec.
- **Anti_Aliasing_Tolerance**: The per-pixel colour distance threshold and edge-pixel rule of the verify spec (`AA_TOLERANCE` in `src/verify/core/constants.ts`).
- **Verify_Tolerance**: The Anti_Aliasing_Tolerance exactly as it is at the start of this spec. This spec does not change it.
- **Exact_Render**: A Rendered_Frame in which zero pixels differ from the Reference_Frame under the Verify_Tolerance (a `matchPercent` of 100 for that frame, with no differing pixel counted by the pixel comparison of the verify spec). The Verify_Tolerance is not widened to reach it.
- **Overall_Match**: The mean `matchPercent` over the compared frames of the Frame_Sample, as defined by the verify spec.
- **Trace_Score**: `100 * matched / max(referenceLineCount, capturedLineCount)`, as defined by the verify spec.
- **Replay**: Running the Reference_Input against the translated classes with the FakeBackend and a ManualClock, as defined by the verify spec (`planReplay` in `src/verify/core/replayPlan.ts`, `replayRunner.ts` in `src/verify/edge/`).
- **Reference_Trace**: `samples/<name>/reference/output.txt`, the Ruffle `trace()` log of the original SWF.
- **Empty_Reference_Trace**: A Reference_Trace file that exists and holds zero lines after `splitTraceLines` (an empty file, or one that holds only line breaks). A sample without an `output.txt` file has no Reference_Trace and is not an Empty_Reference_Trace.
- **Approved_Reporting_Change**: The change of Requirement 14.24 to how behaviour is reported for an Empty_Reference_Trace. It is not one of the Approved_Measurement_Changes, because it computes no new score and raises none.
- **Reference_Input**: `samples/<name>/reference/input.json`.
- **Reference_Options**: `samples/<name>/reference/test.toml`, the Ruffle test options file. Its keys `num_frames`, `num_ticks` and `tick_rate` are defined in Appendix A.8.
- **Input_Group**: The group of Reference_Input entries up to and including the next `Wait` entry, as defined by the verify spec. Ruffle delivers one such group after each tick (Appendix A.8, A.9).
- **Pointer_Entry**: A Reference_Input entry of type `MouseDown`, `MouseMove` or `MouseUp`.
- **Hit_Target**: The nearest ancestor-or-self of the display object that `hitTest` returns for a stage point that is interactive (a `Sprite` or `MovieClip`, that is a `DisplayObjectContainer`, in the Shim; Flash also counts `SimpleButton` and `TextField`, which the Shim does not have yet), or the Stage_Object when `hitTest` returns nothing. A `Shape`, a bitmap, static text or a morph shape is never a Hit_Target. `mouseEnabled` and `mouseChildren` are not modelled (Known limit, design section 10).
- **Pressed_Target**: The Hit_Target at the position of the last applied `MouseDown`.
- **Approved_Measurement_Changes**: The three changes to how a sample is measured that the user approved in advance: (a) reading `num_ticks` as well as `num_frames` (Requirement 14.12 to 14.14), (b) replaying `MouseDown`, `MouseMove` and `MouseUp` as separate pointer events (Requirement 14.3 to 14.9), and (c) replaying a Reference_Trace that has no Reference_Input with empty input for the tick count of the Reference_Options (Requirement 14.23). Requirement 1.7 states the one condition.
- **Licence_Directory**: The directory `samples/LICENSES/` of the Repository. It holds the one copy of each third-party licence text that a PROVENANCE.md points to.
- **Known_Visual_Limit**: One entry of `visual.knownVisualLimits` in the Fidelity_Report. It names a feature that the render path does not draw, or draws only approximately, with a `kind` and a `message`.
- **Named_Limit**: A Known_Visual_Limit or an Unsupported_Feature_List entry that names the feature and, where known, the character id or placement.
- **Unsupported_Feature_List**: `unsupported-features.json` next to the Emitted_Project.
- **Emitted_Project**: The Vite + TypeScript + PixiJS project written by Emit.
- **Boot_File**: `src/main.ts` of the Emitted_Project, copied from `template/src/main.ts`.
- **Candidate_Source**: The Ruffle repository, `github.com/ruffle-rs/ruffle`, directory `tests/tests/swfs`, pinned at commit `4a8d39661ed8aec97afee1504a4e33080da2efd0` (master when checked).
- **Breadth_Sample**: A SWF added to `samples/` by this spec.
- **Approved_Sample_List**: The eight SWFs listed in Requirement 3.1 and in Appendix A.2, approved by the user: seven Committed_Samples and one Fetched_Sample.
- **Committed_Sample**: An Approved_Sample_List SWF whose `test.swf` is stored in the Repository under `samples/<name>/`.
- **Fetched_Sample**: An Approved_Sample_List SWF that is not stored in the Repository. It is `avm2/static_text`. A Fetch_Script downloads it into `.work/samples/<name>/`.
- **Fetch_Script**: The script of Requirement 20 that downloads a Fetched_Sample from the Candidate_Source at the pinned commit, checks its SHA-256 and refuses on a mismatch. No test runs it.
- **Package_Qualified_Class**: A class whose AS3 name has a package, written `pkg.Cls` (dots) in the SymbolClass list and declared in `scripts/pkg/Cls.as`.
- **Qualified_Name**: The dotted name of a class (`pkg.Cls`; `Cls` for a class in the unnamed package). It is the registry key in `src/classes.ts` and the class name in Scene_JSON.
- **Stage_Object**: The minimal Shim object of Requirement 19 that is the parent of the root clip and returned by `DisplayObject.stage`.
- **Replay_Result**: The behaviour result that the Replay hands to the Verify_Stage: the captured trace lines (including those captured before a failure), the `unsupported-input` and `unpaired-mouse-event` entries, the `release-outside` entries of Requirement 14.20, and the failure of a Replay that throws (Requirement 14.22). The Fidelity_Report copies it.
- **Problems**: The list `problems` of the behaviour result of the Fidelity_Report, which holds the defects of a run: `unsupported-input`, `unpaired-mouse-event` and the failure of a Replay that throws (Requirement 14.22).
- **Input_Notes**: The list `behaviour.replay.inputNotes` of the Fidelity_Report. It holds the `release-outside` entries, which explain a missing `click` and are not defects of the run, and also a copy of the `unsupported-input` and `unpaired-mouse-event` entries (Requirement 14.21).
- **Implicit_This_Resolution**: The rewrite of Requirement 22 that turns a bare identifier inside a class body into `this.<name>` or `<Class>.<name>`.
- **Shim_Member_Table**: The table of instance members of the Shim classes that Implicit_This_Resolution reads, generated from the declarations of `template/shim/` (Requirement 22.5).
- **Class_Failure**: A class that cannot load: (a) a linked class with no source and no override, (b) a translated class whose emitted file has a syntax error or was not produced, or (c) a translated class whose emitted file has an import specifier that does not resolve to an emitted file (Requirement 23.1). A class with only type errors is not a Class_Failure.
- **Loose_Class**: A registered translated class whose emitted file has type-check gate diagnostics that are not a Class_Failure. It stays in `src/classes.ts` and is reported with its diagnostics (Requirement 23.2).
- **Registry_Fallback**: The omission of a class with a Class_Failure from `src/classes.ts`, after which the Player instantiates its symbol as the plain base class `MovieClip` (Requirement 23).
- **Timeline_Only_Mode**: The mode of the Boot_File selected by the query parameter `?timelineOnly=<n>` (`template/src/timelineOnly.ts`), in which the Player runs with an empty class registry so that every symbol is a plain `MovieClip`.
- **Diff_Image**: A PNG of the same size as the two compared frames that marks the differing pixels, as defined by the verify spec.
- **Residual_Cause**: The cause to which one differing region of a Diff_Image is attributed under Requirement 21.
- **Score_Floor**: A numeric constant in a test that the measured Overall_Match or Trace_Score of a sample must meet or exceed.
- **Ratchet_Rule**: A Score_Floor is only ever raised, never lowered.
- **Convert**: The pipeline stage `src/convert/` that turns FFDec output into Scene_JSON and shape assets.
- **Scene_JSON**: The canonical scene file the Convert stage writes into the Emitted_Project.
- **Render_Path**: The way the FFDec export of a shape (or of a Static_Text character) becomes pixels in the Emitted_Project.
- **Chosen_Render_Path**: The one Render_Path that the design selects under Requirement 7.
- **SVG_Rewrite_Path**: Render_Path (a). Convert or the backend rewrites the FFDec SVG until Pixi 8.22 `Graphics.svg()` draws it as FFDec intends.
- **Shape_JSON_Path**: Render_Path (b). `Graphics.svg()` is not used. Convert turns each shape into a Shape_JSON and the backend draws it with the Pixi Graphics API.
- **Shape_JSON**: A small JSON description of one shape: fills, gradients with their matrices, bitmap fills, line styles (including cap, join and miter limit) and path commands. It exists only if the Shape_JSON_Path is chosen.
- **Raster_Texture_Path**: Render_Path (c). The SVG is rasterised in the browser and drawn as a texture.
- **Shape_Function**: The pure Core function that the Chosen_Render_Path adds to Convert or the backend load path, for example the SVG rewrite of the SVG_Rewrite_Path or the Shape_JSON builder of the Shape_JSON_Path.
- **Probe_Shapes**: The four shapes used by Requirement 7: one Gradient_Fill, one Bitmap_Fill, one Static_Text character and one stroke with a round line cap, each taken from an Approved_Sample_List SWF.
- **Gradient_Fill**: A shape fill that FFDec exports as `fill="url(#gradientN)"` with a `linearGradient` or `radialGradient` in `<defs>`, with `gradientTransform`, `spreadMethod` and stops.
- **Bitmap_Fill**: A shape fill that FFDec exports as a `<pattern>` holding an `<image>` with a base64 `data:image/PNG` or JPEG URL.
- **Static_Text**: A `DefineTextTag` or `DefineText2Tag` character, exported by FFDec as `texts/<id>.svg` when `-format text:svg -export text` is given.
- **Dynamic_Text**: A `DefineEditTextTag` character.
- **Mask_Layer**: A placement with `clipDepth` set. It masks every placement on the same timeline with a depth above the mask depth up to and including `clipDepth`.
- **Trivial_Mask**: A Mask_Layer whose character is a shape, or a sprite whose frames place only shapes, with any matrix and no colour transform, no filter and no further Mask_Layer inside.
- **Case_Collision**: Two emitted files whose paths differ only in letter case, in the file name or in any directory segment, such as `src/Main.ts` and `src/main.ts`, or `src/Foo/A.ts` and `src/foo/B.ts` (the directories `Foo` and `foo` collide).
- **Core**: Pure modules with no file, process, network, clock, randomness or locale-dependent call.
- **Edge**: Modules that perform I/O.
- **FFDec**: The JPEXS Free Flash Decompiler command line, run only as a separate process.

## Requirements

### Requirement 1: Score integrity

**User Story:** As the project owner, I want scores that cannot be raised by weakening the measurement, so that the fidelity numbers can be trusted.

#### Acceptance Criteria

1. THE implementer SHALL NOT raise any Overall_Match or Trace_Score by changing the Anti_Aliasing_Tolerance, the Frame_Sample rule, the frame count K, the comparison rules of the verify spec, or any file under `samples/*/reference/`, except for the three Approved_Measurement_Changes (the `num_ticks` reading, the separate pointer events and the empty-input Replay) under the condition of criterion 7.
2. WHEN a task changes how a sample is measured instead of how it is rendered, THE implementer SHALL stop and ask the user before continuing, except for the three Approved_Measurement_Changes under the condition of criterion 7.
3. THE Score_Floor of every existing and every Breadth_Sample SHALL follow the Ratchet_Rule.
4. WHEN a task raises the measured Overall_Match or Trace_Score of a sample, THE task SHALL raise the matching Score_Floor in the same commit.
5. IF a change lowers the measured Overall_Match or Trace_Score of any sample below its Score_Floor, THEN THE implementer SHALL fix the change or revert it, and SHALL NOT lower the Score_Floor.
6. THE final summary of each task SHALL state, for each affected sample, the Overall_Match and the Trace_Score before and after the task.
7. WHEN a task implements one of the three Approved_Measurement_Changes, THE implementer SHALL proceed without asking only while all of these hold after the change: the Trace_Score of `clickgoto` is 100, the tick count of the `clickgoto` Replay equals its count before the change (32 when this spec was written, from `num_frames = 32`), the Overall_Match of `clickgoto` and `tweendemo` is at its Score_Floor, and the Trace_Score Score_Floor of `clickgoto` is unchanged.
8. IF a condition of criterion 7 fails, or the Ruffle semantics of Appendix A.8 or A.9 cannot be mapped onto the fixed-step ManualClock of the Replay, THEN THE implementer SHALL stop and ask the user, and SHALL NOT change a Score_Floor, a reference file or the Verify_Tolerance to make the condition hold.
9. THE exception of criterion 7 SHALL cover no change to how a Breadth_Sample is measured other than the three Approved_Measurement_Changes.
10. WHEN a task implements the empty-input Replay of Requirement 14.23, THE condition of criterion 7 SHALL apply to it unchanged: `clickgoto` has a Reference_Input and so keeps Trace_Score 100 and 32 ticks, and `tweendemo` has no `reference/` directory and stays `not-compared`.
11. THE Approved_Reporting_Change of Requirement 14.24 (an Empty_Reference_Trace is reported as `not-compared` with the reason `empty-reference-trace`) SHALL be approved in advance for reporting only, SHALL NOT raise or lower any Overall_Match or Trace_Score, and SHALL hold the condition of criterion 7 without change: the Reference_Trace of `clickgoto` is not empty, so its Trace_Score stays 100 with 32 ticks, and `tweendemo` stays `not-compared` because it has no Reference_Trace.

### Requirement 2: No silent wrong output

**User Story:** As a user, I want every feature that is not drawn correctly to be named in the report, so that a low or high score never hides a cause.

#### Acceptance Criteria

1. WHEN Convert meets a character, placement or fill that the Chosen_Render_Path does not draw correctly, THE Pipeline SHALL record a Named_Limit for it in the Unsupported_Feature_List.
2. WHERE the Verify_Stage runs, THE Fidelity_Report SHALL list in `visual.knownVisualLimits` a Known_Visual_Limit for each Named_Limit of a visually relevant kind.
3. THE set of visually relevant kinds in `src/verify/core/limits.ts` SHALL include every kind this spec adds, and every Known_Visual_Limit SHALL name its `kind`, the character id or placement it applies to, and a message that states what is wrong in the render.
4. IF a feature is approximated, THEN THE Pipeline SHALL record it as a Known_Visual_Limit with a message that says `approximated` and states the difference.
5. THE Pipeline SHALL NOT drop a character, placement or fill without a Named_Limit.
6. WHEN the Chosen_Render_Path has no way to draw an element or attribute that the FFDec export of a shape holds (for example an SVG element that Pixi `Graphics.svg()` reports as unsupported), THE Pipeline SHALL have recorded a Named_Limit for that shape before the Emitted_Project is built.
7. THE Core builders of Named_Limits SHALL produce the same entries in the same total order for the same input.
8. FROM the task that introduces the Shape_Function, THE Shape_Function SHALL return a Named_Limit for every Gradient_Fill (kind `gradient-fill`) and every Bitmap_Fill (kind `bitmap-fill`) that it converts, and THE Pipeline SHALL record each in the Unsupported_Feature_List and in `visual.knownVisualLimits`; THE task that draws gradients (Requirement 8) and THE task that draws bitmap fills (Requirement 9) SHALL remove the Named_Limit only for the cases they draw. THE implementer SHALL NOT commit a state in which a Gradient_Fill or Bitmap_Fill is drawn wrongly or not drawn and reported only by a `console.warn`, and THE backend SHALL NOT skip a fill without a Named_Limit for it.
9. FOR ALL shapes that the Shape_Function converts, EVERY Gradient_Fill and Bitmap_Fill in the input SHALL appear in the output either as a fill that the committed drawing code draws or as exactly one Named_Limit that names its shape id, and no fill SHALL appear as neither (property).

### Requirement 3: Sample admission rules

**User Story:** As the project owner, I want each added sample to be licensed, documented and guarded by a floor, so that the repository stays clean and regressions are caught.

#### Acceptance Criteria

### Requirement 4: SWF without a SymbolClass tag

**User Story:** As a user, I want a SWF that has no linked classes to convert, so that timeline-only files work.

### Requirement 5: Placements of unsupported characters

**User Story:** As a user, I want a SWF with text or buttons to convert and tell me what was dropped, so that one unsupported character does not abort the whole conversion.

#### Acceptance Criteria

1. THE FFDec XML name table in `src/convert/ffdecXml.ts` SHALL read the character id of `DefineTextTag`, `DefineText2Tag` and `DefineEditTextTag` from the attribute `characterID`, and of `DefineButton2Tag` from the attribute `buttonId`, as observed on FFDec 26.4.0 in the files listed in Appendix A.
2. WHEN the table reads an id for a tag of an unsupported kind, THE Convert stage SHALL record the observation with that character id.
3. WHEN a placement refers to a character of kind `text`, `sound`, `button` or `video`, THE Convert stage SHALL drop the placement and SHALL record a Named_Limit with the kind, the sprite id, the frame and the depth, except for a Static_Text character that the Chosen_Render_Path draws (Requirement 10).

6. FOR ALL generated models in which every placed character id is defined as a shape, a sprite or an unsupported character, THE Convert stage SHALL NOT throw `UnknownSymbolError`, and the number of recorded dropped-placement entries SHALL equal the number of dropped placements (property).
7. THE Convert stage SHALL treat a `DefineBits*`, `JPEGTables` or font definition tag as a non-placed definition and SHALL NOT drop any placement because of it.

### Requirement 7: Render path selection

**User Story:** As the project owner, I want the way shapes are drawn to be chosen by measurement against the FFDec frames, so that the render is as close to the original as the effort allows and the choice is on record.

#### Acceptance Criteria

1. THE design SHALL compare at least these three Render_Paths: (a) the SVG_Rewrite_Path, (b) the Shape_JSON_Path and (c) the Raster_Texture_Path.
2. THE design SHALL compare the Render_Paths with throwaway renders of the four Probe_Shapes (one Gradient_Fill, one Bitmap_Fill, one Static_Text character, one stroke with a round line cap), and SHALL score each render against the Reference_Frame under the Verify_Tolerance.
3. FOR EACH Render_Path, THE design SHALL record the matchPercent on every Probe_Shape, the behaviour under scale and under rotation, the impact on hit testing, and the effort (files and functions to add or change).
4. THE design SHALL select exactly one Render_Path as the Chosen_Render_Path and SHALL justify the choice with the values recorded under criterion 3.
5. WHEN the design has selected the Chosen_Render_Path, THE design SHALL delete the throwaway renders and their scripts and SHALL keep the recorded values in `design.md`.
6. WHERE the design uses Chromium's native render of an SVG, THE design SHALL treat it as a diagnostic aid only, and THE acceptance measure of every visual requirement SHALL be the Reference_Frame.
7. THE Shape_Function SHALL be a Core function that returns the same output for the same input.
8. WHERE the output of the Shape_Function has the same form as its input (the SVG rewrite of the SVG_Rewrite_Path), THE Shape_Function SHALL map its own output to itself when applied again (idempotence property).
9. THE Shape_Function SHALL return, with its output, the list of Named_Limits for parts it cannot convert, and SHALL NOT drop a part without an entry in that list.
10. WHERE the Shape_JSON_Path is the Chosen_Render_Path, THE Shape_JSON printer and parser SHALL satisfy parse(print(x)) equals x for every valid Shape_JSON x (round-trip property), and THE Shape_JSON validator SHALL reject a malformed Shape_JSON with a message that names the failing field.

12. THE user has approved the Shape_JSON_Path as the Chosen_Render_Path. THE design SHALL still record the values of criterion 3 for all three Render_Paths, and IF the measured matchPercent of the Shape_JSON_Path on a Probe_Shape is lower than that of another Render_Path, THEN THE design SHALL state the difference and the reason, and SHALL ask the user before it selects another Render_Path.

### Requirement 22: Implicit this resolution

**User Story:** As a user of translated code, I want a bare member name inside a class body to resolve as it does in ActionScript, so that code such as `initx = joystick.x`, `addEventListener(MouseEvent.MOUSE_DOWN, dragPressHandler)` and `stage.addEventListener(...)` runs and type-checks without hand edits.

Facts about the Translate stage when this requirement was written (read from `src/translate/rewrite.ts`, `emitTs.ts`, `planTranslate.ts` and `shimNames.ts`): `ExprRewriter.qualifies` writes `this.` only before a bare name that is followed by `(`, that is in the hand-written set `SHIM_MOVIECLIP_MEMBERS` or in the own non-static method names (`collectOwnMethods`, accessors and the constructor excluded), and that is not in `ctx.locals`; `ctx.locals` holds the parameters and every `var`/`const` name declared anywhere in the function body, including nested blocks and `for` initialisers (`collectLocals` in `emitTs.ts`), which is hoisting to function scope; bare field names, bare static names and bare Shim properties are not qualified, which gives TS errors 2663, 2662, 2552 and 2304 and a `ReferenceError` at run time (measured in the design on `Interactivity3` and `MainTimeline`); `scan` marks `try`, `switch`, `with`, `delete`, `namespace`, `use`, `include` and `function` statements as unsupported, and `emitTs.ts` comments those out, so no catch variable or nested function name reaches the rewriter today.

#### Acceptance Criteria

1. WHEN a bare identifier is a reference in an expression inside the body of a class, and it is not a local, a parameter, a catch variable, a nested function name, an import, or a global, THE Translate stage SHALL resolve it by the first of these rules that matches, in this order, and SHALL emit the text that the rule gives: (1) an own instance member of the enclosing class (field, method, accessor or constant, any visibility) gives `this.x`; (2) a static member gives `Cls.x`, where the candidates are, in this order, an own static member of the enclosing class (`Cls` is the simple name of the enclosing class) and then an inherited static member of a translated superclass, taken along the `extends` chain through every translated class (identified by Qualified_Name under Requirement 18), which gives `Declaring.x` with `Declaring` the class of the chain that declares the static member, bound by its Qualified_Name (the Translate stage SHALL add the import of `Declaring` under Requirement 18.4 and 18.5 when the file does not import it yet); (3) an inherited instance member of a translated superclass, taken along the same chain, gives `this.x`; (4) an instance member of a Shim class that the `extends` chain reaches (for example `x`, `y`, `stage`, `parent`, `mouseX`, `mouseY`, `addEventListener`, `gotoAndStop`) gives `this.x`, using the Shim_Member_Table of criterion 5. THE whole order SHALL be applied as one walk of the `extends` chain from the enclosing class up to the Shim class: the first class of the chain that declares the name, as an instance member or as a static member, decides, so that a name declared as an instance member in one class and as a static member in another class of the chain is resolved by the nearest class; WHERE one class declares the name in both kinds, the instance member wins (rule 1 before rule 2). A translated superclass that has no source, or a chain that ends at a class that is neither translated nor a Shim class, is handled by criterion 6.
2. THE Translate stage SHALL NOT treat as a reference, and SHALL NOT rewrite, an identifier that follows `.` or `::`, that is the declared name of a variable, parameter, function, label or class, that is a key of an object literal, or that lies in a type annotation. THE set of globals SHALL be a constant of the Translate stage that holds the AS3 top-level names (`Math`, `Number`, `String`, `Array`, `Object`, `Boolean`, `int`, `uint`, `Vector`, `Date`, `Error`, `NaN`, `Infinity`, `undefined`, `trace`, `parseInt`, `parseFloat`, `isNaN`, `isFinite`; the design lists the complete set), and an import binding or a Shim class name SHALL be resolved as it is today and never as a member.
3. WHEN a name is declared as a parameter or by `var` or `const` anywhere in a function body (including a nested block, a `for` initialiser or a `for-in` declaration), THE Translate stage SHALL treat the name as a local in the whole function, including at occurrences before the declaration (hoisting to function scope), and SHALL leave every occurrence unchanged. WHERE the scanner represents a catch variable or a nested function name, THE Translate stage SHALL treat it as a local in the same way; WHERE the scanner marks the construct as unsupported, THE Translate stage SHALL rewrite nothing inside it.
4. WHILE the enclosing member is static (a static method, a static accessor or the initialiser of a static field), THE Translate stage SHALL apply rule (2) only (the own static member, then the inherited static member of a translated superclass, which gives `Declaring.x`); an identifier that names an instance member of the class, of a translated superclass or of a Shim class in that position SHALL stay as written and get the diagnostic of criterion 6, whose message says that an instance member is used in a static context.
5. THE Shim_Member_Table SHALL be generated from the declarations in `template/shim/` and SHALL NOT be written by hand. A Core function SHALL take the declaration text of the Shim files and return, for each class that `template/shim/index.ts` exports, its `extends` name and its own non-private instance members (methods, getters, setters and fields whose names do not start with `_`), each with the kind `method` or `property`; an Edge script run by `npm run gen:shim-members` SHALL write the result as sorted data to `src/translate/shimMembers.generated.ts` with a header that names the command; that file SHALL be committed; and a test SHALL regenerate the table from the current `template/shim/` in memory and SHALL fail, naming `npm run gen:shim-members`, when the committed file differs, so that a Shim change that is not followed by the generation cannot be committed. THE hand-written `SHIM_MOVIECLIP_MEMBERS` SHALL be removed. THE generator SHALL need no New_Dependency and SHALL NOT import `typescript-js` from any file other than the two named in `.kiro/steering/tech.md`; IF it needs one, THEN THE implementer SHALL stop and ask the user (Requirement 15.12).
6. IF an identifier is a reference and resolves to nothing, or the `extends` chain ends at a class that is neither translated nor a Shim class (so that rules (3) and (4) cannot be decided), THEN THE Translate stage SHALL leave the identifier as written and SHALL record a Diagnostic of the new kind `unresolved-identifier` with the line, the name and, for an unknown base, the name of the base class; THE Translate stage SHALL NOT hide the Diagnostic, and it SHALL appear in the Translation_Report like the existing kinds.
7. THE rules of criterion 1 SHALL replace the qualification of bare calls by `ExprRewriter.qualifies`: a bare call to a name that rule (1), (3) or (4) resolves SHALL be written `this.name(` as before, and a bare call to a static method SHALL be written `Cls.name(` (own static) or `Declaring.name(` (inherited static of a translated superclass).
8. THE task SHALL add property tests (fast-check) for: shadowing (a local or parameter with the same name as a member of any of the four rules leaves the identifier unchanged); hoisting (a `var` declared after, inside a nested block or in a `for` initialiser still shadows an earlier occurrence in the same function); static versus instance (rule order (1) before (2), rule (2) in a static member, and the static-context diagnostic); inherited static (a static member of a translated superclass, reached through any chain of translated classes, gives `Declaring.x` with `Declaring` the class of the chain that declares it, and the file imports `Declaring`); static versus instance in a chain (for generated `extends` chains in which the same name is declared as an instance member in some classes and as a static member in others, the nearest declaring class decides the kind, an own instance member gives `this.x`, an own static member gives `Cls.x`, and a name declared in both kinds in one class gives `this.x`); method-as-value binding (a method name used as a value gives `this.name` and exactly one `this.name = this.name.bind(this);` statement in the constructor, a method that is only called gives none, and a class without a constructor gets one that calls `super` with its arguments, per criterion 13; this one is an example test as well as a property); and inherited from the Shim (every member of the generated Shim_Member_Table, reached through any chain of translated classes ending at a Shim class, gives `this.x`, and a name that is in no table gives the criterion 6 Diagnostic). THE property tests SHALL also check that the output is the same for the same input (determinism).
9. THE translated output of `samples/clickgoto` and `samples/tweendemo` after this requirement SHALL be byte-identical to the output before it; IF a byte differs, THEN THE task SHALL list each differing line with the rule that caused it and the reason, before the commit, and SHALL NOT change the Trace_Score or the Overall_Match of either sample (Requirement 1.7).
10. THE task SHALL add example tests that translate the lines of the fixtures that motivated this requirement: the bare `stage` of `Interactivity3.as:39`, the bare own fields and methods of `Interactivity3` (`initx = joystick.x` and `addEventListener(MouseEvent.MOUSE_DOWN, dragPressHandler)`), and the bare `mouseX` and `mouseY` of `MainTimeline.as:42`, and SHALL show that the type-check gate reports no error 2663, 2662, 2552 or 2304 for them. Other diagnostics of those classes (for example `with` at `Interactivity3.as:58`, or `MouseEvent.MOUSE_DOWN` before Requirement 14.10) SHALL stay reported.
11. THE measured Trace_Score of `3_joystick` SHALL NOT be accepted as an outcome of this requirement when it stays low because own fields, own methods or Shim members are written unqualified: IF the Trace_Score of `3_joystick` is below the value that its remaining diagnostics explain, THEN THE checkpoint of Requirement 16.2 SHALL name the remaining cause of each missing line.
12. THE task plan SHALL place the task of this requirement with the package work, after the tasks of Requirement 18 that give classes their Qualified_Names and before any task that commits a Breadth_Sample (Requirement 18.12), and every commit that changes `src/translate/` SHALL use the commit area `Translate` (Requirement 15.10).
13. WHEN a bare name that rule (1) or (3) resolves to an instance method of a translated class is used as a value (passed as an argument, assigned, or returned, and not called and not followed by `.`), as in `addEventListener(MouseEvent.MOUSE_DOWN, dragPressHandler)`, THE Translate stage SHALL write the reference as `this.name` and SHALL emit, in the constructor of the class whose body holds the reference, the statement `this.name = this.name.bind(this);` once per such method name, after the call to `super` and before the other statements of the constructor, in the order of first reference in the source. WHERE the class declares no constructor, THE Translate stage SHALL emit a constructor that holds these statements and calls `super` with the arguments it receives. THE same rule SHALL apply to an explicit `this.name` used as a value. THE rule SHALL NOT apply to a static method, to a method that is only called, or to a member of a Shim class.

### Requirement 23: A class that cannot load never costs the visual score

**User Story:** As a user, I want a class that cannot load to be left out of the registry and named in the report, so that the Emitted_Project always builds and still renders its timeline, and the Overall_Match never falls because a class was linked; and I want a class that only has type errors to stay registered and be reported as loose, because it still loads.

Facts when this requirement was written (read from `src/emit/planEmit.ts`, `src/pipeline/pipeline.ts`, `src/translate/typeCheckGate.ts`, `template/tsconfig.json`, `template/runtime/player.ts` and `template/src/timelineOnly.ts`): `buildClassesTs` imports every linked class that has an emitted source and registers it; the type-check gate (`typeCheckProject`) runs after Emit on the emitted files, returns `GateError`s that hold `file`, `line`, `column`, `code` and `message` and no diagnostic category, and builds them from `getPreEmitDiagnostics`, which mixes option, global, syntactic and semantic diagnostics; the emitted `tsconfig.json` uses `moduleResolution` `Bundler`; `Player.createClip` instantiates `MovieClip` for a symbol whose class name is missing from the registry and logs a `console.warn`; `runTimelineOnly` builds the Player with an empty registry; and a constructor that throws stops the Player.

Rationale (decided by the user): Vite transpiles TypeScript and does not type-check, so a file with type errors still loads and runs; the visual score is measured in Timeline_Only_Mode, where the registry is empty and class code does not run; and a runtime throw of a registered class is captured by the Replay, which keeps the lines captured before the failure and names the failure in `problems` (Requirement 14.22). A class therefore costs the build only when its module cannot load: the file does not parse, the file is missing, or an import of the file does not resolve. Only that case justifies leaving a class out of the registry.

#### Acceptance Criteria

1. A Class_Failure SHALL be a class that cannot load, defined by exactly these three cases: (a) a linked class (a Scene_JSON sprite symbol with a `className`) for which Translate produced no class and no handwritten override supplied one (reason `missing-source`); (b) a translated class whose emitted file has a syntax error, that is, at least one `GateError` for that file that comes from the syntactic diagnostics of the TypeScript program (the parse errors, codes of the form TS1xxx that the parser or scanner reports, for example 1002, 1005, 1109, 1128), or whose file Emit failed to produce (reasons `syntax-error` and `emit-failed`); (c) a translated class whose emitted file has an import specifier that does not resolve to an emitted file, that is, a `GateError` for that file with code 2307 (`Cannot find module`) or 2792 (`Cannot find module. Did you mean to set the moduleResolution option`) whose specifier is a relative path and not the Shim (`shim`) or the runtime (`runtime`) of the Emitted_Project (reason `unresolved-import`, with the specifier). A relative specifier is one that starts with `.`; a package specifier such as `pixi.js` is not part of case (c).
2. A `GateError` of any other code in the emitted file of a translated class SHALL NOT make the class fail, and the class SHALL stay in `src/classes.ts`: this holds for every semantic diagnostic (for example 2304, 2322, 2339, 2345, 2551, 2552, 2662, 2663, 2305 and 2306) and for the TS1xxx codes that the checker (not the parser) reports. The class is a Loose_Class: its diagnostics SHALL stay reported through the type-check gate result and the Translation_Report as today, type errors stay not fatal, and no `class-omitted` entry SHALL be written for it. The classification of criterion 1(b) needs to tell parser diagnostics from checker diagnostics, and the code alone does not (several TS1xxx codes are checker errors); THEREFORE the result of the type-check gate SHALL mark each `GateError` that comes from the syntactic diagnostics of the program as syntactic, and the omission SHALL read that mark and not a range of codes. A `GateError` whose `file` is not the emitted path of a class file (`src/classes.ts`, `src/main.ts`, `runtime/`, `shim/`) SHALL NOT make a class fail. A class provided by a handwritten override (the `handwritten/` override rule of `.kiro/steering/structure.md`) is exempt from cases (b) and (c): its errors stay reported only, and it is never omitted for them.
3. WHEN a class has a Class_Failure, THE Emit stage SHALL leave the class out of `src/classes.ts` (no import and no registry entry) and SHALL still write its file when it exists. Omission SHALL propagate, repeated until no further class is added: (i) to every translated class whose `extends` chain contains an omitted class (reason `extends-omitted`, with the name of the omitted base), and (ii) to every translated class whose emitted file imports an omitted class (reason `imports-omitted`, with the Qualified_Name of the omitted class), because the import of an omitted class resolves to a module that cannot load or to no file. After this step `src/classes.ts` SHALL hold no class whose `extends` chain or imports hold an omitted class.
4. WHEN a symbol's class name is not in the registry, THE Player SHALL instantiate the symbol as the plain base class `MovieClip` (the class that an unlinked sprite symbol gets), so that the Rendered_Frame is that of the timeline alone, and THE Emitted_Project SHALL build with `npm run build` and SHALL render in Timeline_Only_Mode whatever the classes contain.
5. THE Overall_Match of `from_shumway/slider_component` SHALL NOT fall below 99.93, and 99.93 SHALL be its Score_Floor from the start of this spec (the value measured before this spec, A.2 and A.3). THE Score_Floor test SHALL be added by the task that admits `slider_component` as a Committed_Sample (Requirement 3.6), because the SWF is not in the Repository before that task; and every task from the first one that links package-qualified classes or changes `src/classes.ts` (Requirements 18, 19, 22 and 23) SHALL verify against the local copy of criterion 6 that 99.93 holds and SHALL state the Overall_Match before and after in its summary (Requirement 1.6).
6. THE implementer SHALL keep a local copy of `slider_component` under `.work/local/slider_component/` (`test.swf`, `output.txt`, `input.json`, `test.toml`, downloaded from the Candidate_Source at the pinned commit, the SHA-256 of `test.swf` checked against `bf6dbcb7...93e9` of Appendix A.2), SHALL create it in the first task that changes the registry or links package-qualified classes, SHALL commit none of it, and SHALL leave it until the task that admits `slider_component` has committed (Requirement 3.17). 7. WHEN a class is left out, THE Pipeline SHALL record a Diagnostic and an Unsupported_Feature_List entry of the kind `class-omitted` that names the Qualified_Name, the reason (`missing-source`, `syntax-error` with the number of syntactic `GateError`s and the first message and line, `emit-failed`, `unresolved-import` with the specifier, `extends-omitted` with the name of the omitted base, or `imports-omitted` with the name of the omitted class), and the ids of the symbols that fall back to `MovieClip`, and THE Translation_Report SHALL list it; THE Pipeline SHALL NOT hide the class, rename it or drop its placements. THE reason `type-errors` SHALL NOT exist.

### A.9 Ruffle input replay: event order

Source: the same pinned commit, downloaded and deleted in the same way.

Delivery. `tests/input-format/src/injector.rs:86` to `122`: `InputInjector::next` walks the entries from its position; a `Wait` ends the group without being delivered (line 96); every other entry is delivered in array order (line 117). `tests/framework/src/runner/automation.rs:19` to `43`: `MouseDown`, `MouseMove` and `MouseUp` become `PlayerEvent::MouseDown`, `MouseMove` and `MouseUp` with the position (and button for down and up). `MouseMove` has `pos` and an optional cursor assertion, no `btn` (`tests/input-format/src/format.rs:124` to `128`). `PlayerEvent`s go to `Player::handle_event` (`core/src/player.rs:1055` to `1071`) and from there to `handle_input_event` (1102).

Order inside one pointer event (`core/src/player.rs`):

1. The stage receives the broadcast clip event (`MouseDown`, `MouseMove`, `MouseUp`) first (1245 to 1249). The pointer position is not updated yet.
2. The pointer position is updated (1341 to 1342), then a dragged object, if any, follows the pointer (`update_drag`, 1346; definition 1433 to 1490: the dragged object's `x` and `y` are set at 1470 to 1471).
3. `update_mouse_state` (1352; definition 1493 to 1880) builds an ordered list of targeted events and dispatches them in that order (1833 to 1846):
   - `MouseMoveInside` first, at the object under the pointer or the stage, only when the position changed (1349, 1520 to 1525). A `MouseDown` or `MouseUp` at a new position therefore dispatches a move first.
   - Roll-out and roll-over events when the hovered object changed (1599 to 1714).
   - For a changed button (1728 to 1826): a press dispatches `Press` at the hovered object and records it as the pressed object (1735 to 1747). A release dispatches `MouseUpInside` at the hovered object (1753 to 1762), then, when the pressed object is the hovered object (1764 to 1767), `Release` at the pressed object (1778 to 1794), otherwise `ReleaseOutside` at the pressed object (1795 to 1807). The pressed object is cleared (1824).

AVM2 events (`core/src/display_object/interactive.rs`, `event_dispatch_to_avm2`): `Press` dispatches `mouseDown` (309 to 322); when no listener handled it, Ruffle only simulates a `click` dispatch to compute the handled flag (323 to 333). `MouseUpInside` dispatches `mouseUp` (335 to 349). `Release` dispatches `click`, or `doubleClick` when double click is enabled and the click index is odd (351 to 379). `ReleaseOutside` dispatches `releaseOutside` (394 to 407). `MouseMoveInside` dispatches `mouseMove` (529 to 542).

Differences from the description given by the user ("`MouseDown` dispatches `mouseDown` at its position, `MouseMove` moves the pointer and dispatches `mouseMove`, `MouseUp` dispatches `mouseUp` at its position, and `click` fires only when press and release hit the same target"):

- (a) `mouseMove` is dispatched only when the position changes, and also before a `mouseDown` or `mouseUp` at a changed position (1520 to 1525). This is not in the description.
- (b) `mouseUp` goes to the object under the pointer at release (the hovered object), which may differ from the pressed object, and comes before `click` (the order in the events list, 1753 and 1778).
- (c) The same-target rule matches the description: `click` is dispatched at the pressed object only if it is the hovered object at release (1764 to 1794). On a mismatch Ruffle dispatches `releaseOutside` at the pressed object instead of `click`; this spec does not replay that event.
